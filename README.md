# CareFlow AI — Gemini Voice Assistant

A responsive hospital-operations hackathon prototype based on the React UI and data files you supplied. It retains the dashboard, patient assistant, appointments, support tickets, inquiries, staff escalation queue, English/Hindi controls, browser speech recognition, and browser text-to-speech. General knowledge questions can now be answered by Gemini through a server-side API so the API key is not exposed in frontend code.

## Requirements
- Node.js LTS (includes npm)
- Internet connection for package installation and Gemini API requests
- Google AI Studio Gemini API key
- Recent Chrome or Edge recommended for browser voice input

## Windows setup — step by step
1. Extract this ZIP to a folder such as `D:\CareFlow_AI_Gemini_Voice_Assistant`.
2. Open that folder in VS Code: **File → Open Folder**.
3. In the VS Code terminal, run:
   ```powershell
   npm install
   ```
4. Make a copy of `.env.example` in the same folder and name the copy `.env`.
5. Open `.env` and replace `PASTE_YOUR_GEMINI_API_KEY_HERE` with your own key. Do not add quotes and do not share the key.
6. Start the app:
   ```powershell
   npm run dev
   ```
7. Open the **Local** URL printed by Vite, normally `http://localhost:5173`.
8. To check the API service, open `http://localhost:3001/api/health`. It should return JSON and `"configured": true` after the key is set.

Stop both services with **Ctrl+C** in the terminal.

## Gemini API key safety
- The browser never receives the API key. The Express server reads it from `.env`.
- Never paste the key into `App.jsx`, `main.jsx`, `index.html`, screenshots, chat messages, or GitHub.
- If a real key was exposed publicly, revoke it and create a new one.
- Do not upload your `.env` file when sharing the project.
- Google AI Studio usage and quotas may change; verify your account's current limits.

## Voice assistant
- Press the microphone button in Patient Assistant, allow microphone access, and speak.
- The browser converts speech to text; the app sends the text to its assistant workflow.
- Gemini answers general questions in the selected language.
- The browser's speech synthesis can read the last assistant response aloud if the UI's speaker/read-aloud control is used.
- Voice recognition support varies by browser and device. If it does not work, use typed chat.

## Data and workflow
- `server/knowledge-base.json` contains demo hospital hours, departments, sample doctors/slots, safety rules, and Indore directory references.
- The existing UI keeps appointments, tickets, leads, escalations, and sample records in the current browser's `localStorage`.
- General questions are routed to Gemini. Existing deterministic workflows still handle recognizable appointment requests, staff escalations, inquiries, emergency messages, and directory questions.
- Appointment slots, doctors, OPD hours, and dashboard records are fictional demo data unless independently verified.
- Data is local to one browser profile; this is not a multi-user hospital system.

## Build check
```powershell
npm run build
```
Vite creates the production frontend in `dist/`. The Gemini API still requires the Node server and `.env` to be configured when running the complete app.

## Suggested demo script
1. Show Overview and the dashboard activity metrics.
2. Open Patient Assistant and ask: “What are the demo OPD hours and what should I bring?”
3. Ask a different follow-up question to demonstrate Gemini's contextual response.
4. Use the microphone and speak in English; switch to Hindi and try again.
5. Ask to book a cardiology appointment tomorrow and enter a fictional patient name.
6. Open Appointments and show the demo confirmation ID.
7. Ask to speak with hospital staff; open Staff Escalations and show the new item.
8. Create a support ticket/inquiry, then refresh to show browser-local persistence.
9. Explain that AI answers are generated by Gemini while transactional demo workflows are confirmed by the app.

## Safety and limitations
- This is a hackathon prototype, not a deployed or verified hospital system.
- Do not enter real patient names, contact details, medical records, passwords, or other sensitive information.
- The sample login/register modal in the supplied UI is only a local demo and is not secure authentication.
- The assistant must not be used for diagnosis, triage, or treatment. In an emergency, contact local emergency services or go to the nearest emergency department.
- Before real deployment, add secure authentication, server-side database storage, authorization, audit logging, rate limiting, monitoring, privacy/security review, verified hospital content, and human-reviewed escalation workflows.
